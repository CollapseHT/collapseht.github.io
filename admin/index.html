內容管理後台

在這裡修改「更新歷程」、「部落格」與「放浪團」的內容。儲存後會直接 commit 到 GitHub， GitHub Pages 大約 1 分鐘後更新前台。

連線到 GitHub

需要一組有 Contents: Read and write 權限的 Fine-grained token。 權杖只會存在這台裝置的 localStorage，不會寫進網站，也不會出現在網址或畫面上。

非擁有者一律透過 Pull Request 送出，由擁有者審核合併。 建議在 GitHub 對 main 開啟分支保護（Require a pull request），這樣權限才是真正被限制。

如何取得 GitHub 權杖？（第一次設定看這裡）
  1. 登入 GitHub，點右上角頭像 → Settings。
  2. 左側最下方 Developer settings → Personal access tokens → Fine-grained tokens。
  3. 按 Generate new token，名稱填 mogumogu-admin，Expiration 選 90 天。
  4. Repository access 選 Only select repositories，只勾 CollapseHT/collapseht.github.io。
  5. Repository permissions → Contents 設為 Read and write（Metadata 會自動變 Read）。
  6. 如果要用「建立 Pull Request」：Pull requests 也設為 Read and write。
  7. 朋友要先被邀請成這個 repo 的 collaborator（Settings → Collaborators），才能用自己的 token 寫入。
  8. Generate token，複製 github_pat_... 貼到上面的欄位。

如果權杖外流，隨時回到 GitHub 撤銷即可；後台只會用它讀寫這個 repo 的檔案。

要讓「只能編輯某一區」真正有效，請到 GitHub → Settings → Rules → Rulesets（或 Branches）， 對 main 開啟「Require a pull request before merging」。 這樣朋友就算繞過後台直接打 API，也只能建立 PR，不能直接改 main。

本機模式是什麼？

在本機用 http://localhost 開啟後台時，可以選「本機檔案模式」： 直接讀取同資料夾的前台 HTML，改完用瀏覽器寫回檔案（或下載三個 HTML）， 不需要 token，適合先在本機預覽、確認版面後再自行 push。

最快的啟動方式：在 collapseht.github.io 資料夾執行 node admin/serve.mjs，再開 http://127.0.0.1:5173/admin/。
