內容管理後台

在這裡修改「更新歷程」、「部落格」、「放浪團」與「Legend 伺服器」的內容。儲存後會依權限直接 commit 或建立 Pull Request， GitHub Pages 大約 1 分鐘後更新前台。

登入後台

用管理員帳號密碼登入。驗證與 GitHub 提交都由 Cloudflare Worker 代勞， 瀏覽器裡不會有任何 GitHub token。

角色由帳號決定；登入後系統會自動確認你對這個 repo 的寫入權限。

先登入，確認身分後再按「載入後台」。

後台是怎麼驗證的？（第一次設定看這裡）

這個頁面是靜態檔，真正的登入與提交由 Cloudflare Worker api.collapseht.org 處理：

  1. 在這裡輸入帳號密碼 → Worker 用 PBKDF2 驗證，通過後發一張 HttpOnly 的簽章 cookie（7 天）。
  2. 存檔時前端只把「要打哪個 GitHub API」交給 Worker，由 Worker 帶著伺服器端的 token 去 commit。
  3. 瀏覽器裡沒有任何 GitHub token，打開 DevTools 也拿不到；外流風險從「每個編輯者手上都有一把鑰匙」變成「只有 Cloudflare 上有」。

要新增或重設帳號：在 cloudflare-admin 專案執行 node scripts/hash-password.mjs "新密碼"，把輸出的雜湊寫進 D1 的 users 表。

要讓「只能編輯某一區」真正有效，請到 GitHub → Settings → Rules → Rulesets（或 Branches）， 對 main 開啟「Require a pull request before merging」。 這樣就算有人繞過後台直接打 API，也只能建立 PR，不能直接改 main。

本機模式是什麼？

在本機用 http://localhost 開啟後台時，可以選「本機檔案模式」： 直接讀取同資料夾的前台 HTML（update、blog、group 與 legend/），改完用瀏覽器寫回檔案（或下載這些 HTML）， 不需要登入，適合先在本機預覽、確認版面後再自行 push。

最快的啟動方式：在 collapseht.github.io 資料夾執行 node backend/serve.mjs，再開 http://127.0.0.1:5173/backend/。
